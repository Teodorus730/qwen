## 0. Общая картина

**Проект одной фразой:** сближаем ученика с учителем не случайными данными, а прицельно — на каждой итерации находим домен, где они расходятся сильнее всего, собираем для него компактный набор текстов без дублей и дообучаем ученика, и так по кругу до сходимости.

Участники: **учитель** (например, `Qwen/Qwen3.5-2B-Base`) и **ученик** (например, `Qwen/Qwen3.5-0.8B-Base`). Пара стартовая — та, что уже в ноутбуке; дальше можно менять.

### Схема цикла

```
        ┌──────────────────────────────────────────────────────┐
        │                                                      │
        ▼                                                      │
  [1. GP-этап]  карта расхождений учитель vs ученик            │
        │        по доменам → выбираем домен с худшей θ̂        │
        ▼                                                      │
  [2. Марковский этап]  coreset по корпусу выбранного домена   │
        │        (относительно ТЕКУЩЕГО ученика)               │
        ▼                                                      │
  [3. Обучение]  дообучаем ученика на coreset ─────────────────┘

  Стоп: θ̂ достаточно высока во всех доменах,
        кончился бюджет или прогресс остановился.
```

Что даёт каждый кусок:

- **GP** отвечает на вопрос «**где** расходятся» — строит карту по доменам, не прогоняя весь пул текстов через обе модели.
- **Марковость** отвечает на вопрос «**какие данные взять**» — из корпуса домена выбирает компактное подмножество, которое покрывает внутренние режимы модели и не содержит дублирующихся по смыслу текстов.
- **Обучение** закрывает найденный разрыв, и цикл повторяется уже для новой версии ученика.

### Задачи и люди

Три задачи. Задачи 1 и 2 делаются параллельно и независимо, задача 3 сшивает их в цикл.

| #   | Задача                     | Вход                                         | Выход                                                                  |
| --- | -------------------------- | -------------------------------------------- | ---------------------------------------------------------------------- |
| 1   | Марковский отбор (coreset) | модель (ученик) + корпус домена              | ранжированный coreset по домену                                        |
| 2   | GP-карта расхождений       | пара моделей (учитель, ученик) + пул доменов | карта «домен → $\hat{\theta}$», худший домен, топ расходящихся текстов |
| 3   | Единый пайплайн (цикл)     | результаты 1 и 2                             | оркестрация цикла + обучение + трекинг + итоговый эксперимент          |

3 задача дополнительно владеет общей инфраструктурой (загрузка моделей, датасеты, окружение, кэши)

## 1. Задача №1 — марковский coreset

Одна функция: **`select_coreset(model, corpus) -> coreset`** — ранжированный (в порядке отбора) список документов одного домена. Вызывается на шаге 2 общего цикла, каждый раз для текущей версии ученика.

Константы модели (Qwen3.5-0.8B): 24 слоя → **23 стыка** $\ell \to \ell{+}1$; FFN каждого слоя — $I = 3584$ нейронов (SwiGLU). Идентификатор пары:

$$
\mathrm{id}(\ell, i, j) = \ell \cdot I^{2} + i \cdot I + j
$$

— одинаковые пары на разных стыках не смешиваются. Теоретический алфавит на стыке — $I^{2} \approx 1.28 \cdot 10^{7}$ пар, живых на реальном корпусе на порядки меньше, поэтому все структуры разреженные, сырые активации не храним.

### Этап 1 — прогон корпуса и частоты пар

1. Хуки на FFN всех 24 слоёв. Активация нейрона $i$ на токене $t$ в слое $\ell$:

    $$
    a_{t,i}^{(\ell)} = \operatorname{SiLU}\!\bigl(W_g\, h_t^{(\ell)}\bigr)_i \cdot \bigl(W_u\, h_t^{(\ell)}\bigr)_i
    $$

2. В каждом слое на каждом токене берём **топ-5 индексов по модулю активации** (ранг, без порога):

    $$
    \mathrm{Top}_5\bigl(a_t^{(\ell)}\bigr) = \operatorname*{arg\,top}_{5}\ \bigl| a_{t,i}^{(\ell)} \bigr|
    $$

3. Событие на стыке $\ell \to \ell{+}1$ — упорядоченная пара $(i, j)$, где $i \in \mathrm{Top}_5(a_t^{(\ell)})$, $j \in \mathrm{Top}_5(a_t^{(\ell+1)})$. До $5 \times 5 = 25$ пар на токен на стык, суммарно $\le 23 \times 25 = 575$ на токен.
4. Два уровня счётчиков: глобальный $n_{ij}^{(\ell)}$ по всему корпусу и на каждый документ $d$ — свой разреженный $n_{d,ij}^{(\ell)}$ (нужен на этапах 2–3). Прогон чанками по документам, в память идут только счётчики.
5. Нормировка:

    $$
    p_{ij}^{(\ell)} = \frac{n_{ij}^{(\ell)}}{N_\ell}, \qquad N_\ell = \sum_{i,j} n_{ij}^{(\ell)}, \qquad \sum_{i,j} p_{ij}^{(\ell)} = 1
    $$

Выход этапа: глобальные частоты $\bigl\{ p_{ij}^{(\ell)} \bigr\}$ + per-document счётчики $\bigl\{ n_{d,ij}^{(\ell)} \bigr\}$.

### Этап 2 — базовые скоры на всём корпусе

Для каждого документа $d$ по его счётчикам $n_{d,ij}^{(\ell)}$:

$$
T(d) = \bigl\{ (\ell, i, j) : n_{d,ij}^{(\ell)} > 0 \bigr\}, \qquad
M(d) = \sum_{(\ell,i,j) \in T(d)} p_{ij}^{(\ell)}, \qquad
\mathrm{score}(d) = \frac{M(d)}{\max(\lvert d \rvert,\, 1)}
$$

где $\lvert d \rvert$ — число токенов документа. Скор — это **масса на токен**: короткий текст с редкими парами ценнее длинного с частыми. Базовые скоры — стартовое заполнение кучи этапа 3.

### Этап 3 — отбор coreset: lazy greedy + binary heap

Отбор по предельному приросту относительно уже выбранного набора $S$ (покрытие $T(S)$ — объединение пар выбранных документов):

$$
\Delta M(d, S) = \sum_{(\ell,i,j)\,\in\, T(d) \setminus T(S)} p_{ij}^{(\ell)}, \qquad
\mathrm{score}(d \mid S) = \frac{\Delta M(d, S)}{\max(\lvert d \rvert,\, 1)}
$$

Цикл lazy greedy (Minoux 1978 / CELF):

1. Заполнить binary max-heap базовыми скорами этапа 2: $\mathrm{score}(d \mid \emptyset)$ для всех $d$.
2. Достать вершину кучи — документ $d_{\text{top}}$; пересчитать его скор $\mathrm{score}(d_{\text{top}} \mid S_{\text{сейчас}})$.
3. Если пересчитанный скор всё ещё $\ge$ ключа новой вершины кучи — взять $d_{\text{top}}$; иначе вернуть его в кучу с обновлённым ключом и снова достать вершину.
4. Взятый документ идёт в coreset; обновляем $T(S) \leftarrow T(S) \cup T(d_{\text{top}})$ и $\mathrm{covered} \leftarrow \mathrm{covered} + \Delta M(d_{\text{top}}, S)$; в лог шага пишем $\bigl( \mathrm{id}(d),\ \Delta M,\ \mathrm{covered},\ |S| \bigr)$. Документы с $\Delta M = 0$ из кучи выбрасываются.
5. Стоп — **колено** кривой «covered vs число документов»: точка максимального отклонения от хорды, соединяющей концы кривой. Кривая строится из лога шагов, поэтому колено можно пересчитать (жёстче/мягче) без перезапуска отбора.

Результат: **coreset по домену** + кривая покрытия.

Контроль воспроизводимости: фиксированный порядок документов и tie-break в куче (по id); для каждого взятого документа $\Delta M(d, S_{\mathrm{final}}) = 0$; $\mathrm{covered}$ монотонна и равна массе $\bigcup_{d \in S} T(d)$.

## 2. Задача №2 — GP-карта расхождений

Одна функция: **build_map(teacher, student, pool) -> карта «домен → $\hat{\theta}$», худший домен,**. Вызывается на шаге 1 общего цикла; учитель фиксирован, ученик от итерации к итерации меняется, поэтому все измерения кэшируются по ключу «текст × пара моделей» и не перемеряются.

Константы брать из [MVP-ноутбука](gaussian_processes/qwen-fe.ipynb)

### Этап 1 — пул доменов и эмбеддинги

1. Собрать пул: по $N = 500$ текстов на домен и, контекст 512 токенов; hold-out 200 текстов; $\kappa = 2$. Список доменов — открытый вопрос, бейзлайн — готовые доменные датасеты.
2. Посчитать эмбеддинги всех текстов пула один раз и закэшировать: между итерациями цикла дистилляции пул не меняется, меняется только ученик.

$z$ — «координата» текста: кластеризация, GP и выбор точек на измерение работают в этих координатах, дорогие прогоны моделей — только там, где решаем измерить.

### Этап 2 — истинное расхождение (дорогая метрика)

Для текста $c$:

1. Токенизация с обрезкой до 128 токенов, прогон через обе модели батчами, логиты на всех позициях $t$; результат измерения — в кэш.
2. На позиции $t$: распределения $\tilde p_t, \tilde q_t$ — softmax логитов, носитель — объединение топ-30 токенов обоих распределений, вероятности ренормируются на носителе.
3. Расхождение позиции:

$$
d_t = \tfrac{1}{2}\, \mathrm{JS}\bigl(\tilde p_t \,\|\, \tilde q_t\bigr)
$$

4. Расхождение текста — среднее по позициям: $d(c) = \frac{1}{T} \sum_{t=1}^{T} d_t$.

Цена одного измерения — два инференса, поэтому меряем малую долю пула; где именно мерить — решает этап 3.

**Стартовая разметка:** внутри каждого домена KMeans на эмбеддингах, 4 кластера × 5 ближайших к центроиду = 20 измерений на домен (120 на пул) — первое покрытие домена до всякого GP.

### Этап 3 — GP-суррогат, active search, карта

**Свой GP на каждый домен** (не один на весь пул): вход — размеченные пары $(z_i, d_i)$ этого домена, ядро RBF. Для любого текста домена GP даёт $\mu(z)$ — предсказанное расхождение и $\sigma(z)$ — неопределённость.

Карта домена — на hold-out (200 непомеренных текстов):

$$
\hat{\theta} = \frac{1}{M} \sum_{j=1}^{M} \Phi\!\left( \frac{\varepsilon - \mu(z_j)}{\sigma(z_j)} \right)
$$

где $\Phi$ — CDF нормального распределения. $\hat{\theta}$ — доля текстов домена с расхождением $\le \varepsilon$ с учётом неопределённости суррогата. Ориентир из MVP (один GP на весь пул): при $\varepsilon = 0.05$ GP-оценка 0.40 против эмпирики 0.415, максимум найденного расхождения 0.143.

Результат: таблица «домен → $\hat{\theta} \pm$ интервал», худший домен (минимальная $\hat{\theta}$) и топ-N расходящихся текстов каждого домена.

Контроль воспроизводимости: seed'ы и конфиги фиксированы; на hold-out сравниваем $\hat{\theta}$ с эмпирической долей $\mathbb{1}[\,d(c_j) \le \varepsilon\,]$ и $\mu$ с истинными $d$ (диаграмма калибровки); кэш измерений переиспользуется между итерациями цикла.

## 3. Задача №3 — единый пайплайн (цикл дистилляции)

### 3.1 Пайплайн

Один проход цикла (итерация):

1. **GP-этап.** Зовём задачу №2: карта «домен → $\hat{\theta}$» для текущей пары учитель/ученик → худший домен.
2. **Марковский этап.** Зовём задачу №1: coreset по корпусу худшего домена относительно текущего ученика.
3. **Обучение.** Дообучаем ученика на coreset (функция потерь — открытый вопрос, бейзлайн: SFT на текстах).
4. **Новая итерация.** Ученик обновился → снова шаг 1. Кэш GP-измерений переиспользуется, поэтому каждая следующая карта дешевле первой.

**Критерий остановки:** $\hat{\theta}$ ≥ порога во всех доменах (ученик «догнал» учителя в пределах $\varepsilon$), исчерпан бюджет итераций/данных, или прогресс по картам остановился.
