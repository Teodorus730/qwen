# Анализ предложенного подхода к датасет-селекции для претрейна LLM 0.6B

**Контекст задачи:**

- Претрейн модели 0.6B параметров с целью воспроизведения качества учителя.
- Учитель: обученная модель той же архитектуры.
- **Ограничение:** отсутствует доступ к тестовому датасету. Есть бенчи, но подгоняться под них, очевидно, нельзя.

**Предложенный подход (тезисы):**

1. Прогнать большой датасет через учителя → получить эмбеддинги и градиенты.
2. Кластеризовать данные по эмбеддингам через DBSCAN.
3. Для каждого кластера вычислить центр масс градиентов.
4. Отобрать малое число представителей, чей суммарный градиент совпадает с направлением центра масс.
5. Сохранить дисперсию каждого кластера.
6. Обучить студента на полученном датасете стандартным способом.

Ниже — возможные проблемы с опорой на современную литературу.

**Оговорочка:**

**Очень, очень, очень просим** ознакомиться с уже проделанной работой: [pipeline.md](pipeline.md) и [dataset_shrinking.md](dataset_shrinking.md). Там по сути примерно те же идеи, только они опираются на готовые статьи. Честно говоря, без оценки сложно - может, это полный бред, но чтобы это понять, нужны Вы) А приступать к выполнению без критической оценки сверху кажется неправильным.

### Проблема 1: Нестационарность градиентов (фундаментальное ограничение)

**Утверждение:** Градиенты, полученные от обученного учителя, можно использовать для отбора данных под студента с рандомной инициализацией.

**Проблема:**
Градиент примера $x$ жестко привязан к текущим весам модели $\theta$:
$$g_i(\theta) = \nabla_\theta L(x_i, \theta)$$

Учитель находится в точке $\theta_{\text{teacher}}$ (финал обучения). Студент стартует из $\theta_0$ (случайная инициализация). Векторы $g_i(\theta_{\text{teacher}})$ и $g_i(\theta_0)$ указывают в принципиально разные направления пространства параметров.

**Литература:**

- В _Dataset Condensation with Gradient Matching_ (Zhao et al., ICLR 2021) [[1]](https://arxiv.org/pdf/2006.05929) градиентный матчинг выполняется **итеративно** в процессе оптимизации синтетических данных, а не статически по финальным весам.
- В _Dataset Distillation by Matching Training Trajectories_ (Cazenavette et al., CVPR 2022) [[2]](https://arxiv.org/pdf/2203.11932) показано, что матчинг градиентов в одной точке (single-step) **не позволяет восстановить траекторию обучения**. Требуется явное выравнивание всей траектории параметров.

**Вывод:** Статический отбор реальных семплов по градиентам учителя на финальных весах математически не обеспечивает сходимость студента к состоянию учителя. Студент получит апдейты, релевантные для точки $\theta_{\text{teacher}}$, но нерелевантные для его собственной траектории от $\theta_0$.

**Углубление (GAIA, arXiv:2606.30077):** Статья _GAIA: Online Data Selection for Instruction Tuning via Gaussian Processes_ (Wang et al., 2026) [[14]](https://arxiv.org/pdf/2606.30077) в разделе Related Works формулирует три фундаментальных ограничения оффлайн (статического) отбора данных:

1. **Высокие вычислительные затраты.** Оффлайн-методы оценки важности данных (Shapley value, influence functions) требуют либо повторного дообучения модели для каждого примера, либо двухуровневой оптимизации (outer loop: подбираем данные, inner loop: обучаем модель и смотрим результат), что масштабируется крайне плохо на LLM.

2. **Нарушение предпосылки стационарности.** Influence-function техники [[6]](https://arxiv.org/pdf/2203.11932) предполагают **локальную линейность** вокруг фиксированных параметров. В сильно невыпуклых ландшафтах LLM это предположение не выполняется — полезность данных эволюционирует по мере изменения весов модели. Следовательно, статическая оценка данных, проведённая один раз до начала обучения, **не отражает реальной informativeness примеров на разных стадиях тренировки**. В нашем случае проблема ещё хуже: веса учителя $\theta_{\text{teacher}}$ и случайная инициализация студента $\theta_0$ — это **принципиально разные области** пространства параметров. Линеаризация вокруг $\theta_{\text{teacher}}$ для задачи студента бессмысленна — это не «локальное отклонение», а полностью чужая точка.

3. **Одноразовый отбор — плохой отбор.** Оффлайн-пайплайны выполняют pruning единожды перед обучением. Однако информативность данных **сдвигается между стадиями обучения** (easy examples полезны в начале, hard — в конце). Однократный отсев неизбежно отбрасывает данные, которые станут критически важными на поздних этапах, и оставляет данные, которые перестанут быть полезными.

    **Оговорочка:** эта проблема **частично решается** стратифицированной выборкой по сложности (Easy / Core / Hard квоты) + перемешиванием данных — именно так предлагается в разделе «Предложение» ниже. Такой подход сохраняет представителей всех уровней сложности на протяжении всего обучения, а перемешивание гарантирует, что модель видит их вперемешку. Критика GAIA направлена в первую очередь против **наивного оффлайн-прунинга** (remove low-score, keep high-score без стратификации), а не против квотирующего подхода. Тем не менее, остаётся ограничение: сами метки сложности (PPL от прокси-модели) вычисляются **статически** и не отражают того, как воспринимает сложность конкретный студент в процессе обучения.

> _"The static nature of offline selection — performing pruning only once prior to training — often yields suboptimal results as data informativeness shifts across training stages."_ — Wang et al., 2026

Это напрямую подтверждает «Проблему 1»: использование градиентов учителя (вычисленных в финальной точке $\theta_{\text{teacher}}$) для статического отбора — это оффлайн-подход, который по определению не способен учесть нестационарность полезности данных. GAIA предлагает **онлайн-селекцию** через Gaussian Process для адаптивного обновления оценки качества данных на каждой итерации.

**Углубление:** Недостаточность выравнивания только первого момента (центра масс или среднего направления градиентов в фиксированной точке весов) для восстановления полной траектории обучения подробно обоснована в работе Cazenavette et al., _Dataset Distillation by Matching Training Trajectories_ (CVPR 2022, [[2]](https://arxiv.org/pdf/2203.11932)). В этой работе показано, что single-step gradient matching (выравнивание градиентов в одной точке) захватывает лишь локальную информацию о текущем шаге оптимизатора. Даже если отобранное подмножество дает математически идентичный средний градиент с полным датасетом в конкретной точке $\theta$, их глобальные траектории параметров $\{\theta_0, \ldots, \theta_T\}$ на длинной дистанции радикально расходятся из-за накопления ошибок и нелинейности ландшафта потерь. Это не просто теоретическое ограничение, а строгий методологический вывод, подтвержденный тем, что методы, матчатящие только градиенты, стабильно проигрывают методам, которые явно выравнивают всю траекторию обучения. Следовательно, одного лишь совпадения «общего направления» градиентов недостаточно для того, чтобы студент в итоге пришел в ту же точку пространства параметров, что и учитель.

### Проблема 2: DBSCAN в высокоразмерных пространствах эмбеддингов

**Утверждение:** Эмбеддинги LLM можно кластеризовать через DBSCAN для выделения тематических групп.

**Проблема:**
Эмбеддинги имеют размерность $d \geq 1024$. В таких пространствах метрики расстояния вырождаются из-за явления концентрации мер (concentration of measure):

$$\frac{\text{dist}_{\max} - \text{dist}_{\min}}{\text{dist}_{\min}} \xrightarrow{d \to \infty} 0$$

Все точки становятся почти равноудаленными, и концепция "локальной плотности", на которой основан DBSCAN, теряет смысл.

**Оговорочка:** технически мы, конечно, можем использовать рандомные проекции, как в trak (см. проблема 3) и по идее проблема решится, но хз, насколько хорошо это будет работать

**Литература:**

- Классическая работа _When Is "Nearest Neighbor" Meaningful?_ (Beyer et al., ICDT 1999) [[7]](https://doi.org/10.1007/3-540-49257-7_15) доказывает, что в высоких размерностях метрики расстояния вырождаются, и алгоритмы, основанные на плотности или расстояниях, дают нерелевантные результаты.
- В современных LLM-пайплайнах (INGENIOUS [[4]](https://arxiv.org/pdf/2305.06677), DCLM [[9]](https://arxiv.org/pdf/2406.11794), FineWeb [[10]](https://arxiv.org/pdf/2410.09335)) для Core-Set Selection используется **Spherical K-Means** или **K-Center Greedy** с косинусным расстоянием, а не DBSCAN.
- **TRAK** (Park et al., 2023) [[13]](https://arxiv.org/pdf/2211.02041) использует Random Feature Projections для понижения размерности градиентов.

**Практическое следствие:** DBSCAN отправит редкие домены в шум (метка `-1`), и они будут безвозвратно удалены. Для претрейна LLM потеря хвостового распределения критична — модель не выучит редкие, но важные языковые конструкции.

**Вывод:** DBSCAN неприменим для кластеризации LLM-эмбеддингов. Необходимо использовать K-Means с косинусным расстоянием.

### Проблема 3: Центр масс градиентов и ортогональность в пространстве параметров

**Утверждение:** Внутри кластера можно вычислить "центр масс градиентов" и отобрать примеры, чей суммарный градиент совпадает с этим направлением.

**Проблема:**
Пространство параметров LLM имеет размерность $p \sim 10^8 - 10^9$. В таких пространствах градиенты случайных примеров практически ортогональны:
$$\cos(g_i, g_j) \approx 0 \quad \text{для } i \neq j$$

Следовательно, сумма градиентов внутри кластера стремится к нулю из-за взаимного гашения:
$$\left\| \frac{1}{|C|} \sum_{i \in C} g_i \right\| \ll \frac{1}{|C|} \sum_{i \in C} \|g_i\|$$

"Общее направление" кластера имеет норму, близкую к нулю, и не несет информации о том, какие примеры полезны.

**Возможное возражение и его ограничение:**
Проблема ортогональности градиентов в полном пространстве параметров **теоретически решаема**. Согласно лемме Джонсона–Линденштраусса, для любого множества из $n$ векторов в $\mathbb{R}^p$ существует линейная проекция (JL-проекция) $f: \mathbb{R}^p \to \mathbb{R}^k$ с $k = O(\epsilon^{-2} \log n)$, сохраняющая попарные расстояния с точностью $(1 \pm \epsilon)$:
$$(1 - \epsilon) \|g_i - g_j\|^2 \leq \|f(g_i) - f(g_j)\|^2 \leq (1 + \epsilon) \|g_i - g_j\|^2$$

Это означает, что градиенты можно спроецировать в пространство значительно меньшей размерности, сохранив их относительную геометрию (углы и расстояния). Именно на этом принципе построены современные методы:

- **TRAK** (Park et al., 2023) [[13]](https://arxiv.org/pdf/2211.02041) использует Random Feature Projections для понижения размерности градиентов.
- **GRAD-MATCH** (Killamsetty et al., 2021) [[8]](https://arxiv.org/pdf/2103.00198) применяет проекции для ускорения вычисления градиентных расстояний.

**Однако** даже корректное восстановление геометрии градиентов через проекции **не решает фундаментальную проблему нестационарности** (Проблема 1). Если градиенты вычислены в точке $\theta_{\text{teacher}}$, их спроецированная геометрия остаётся геометрией точки $\theta_{\text{teacher}}$. Студент, стартующий из $\theta_0$, будет иметь принципиально другую геометрию градиентов, и "центр масс", корректно вычисленный через JL-проекции для учителя, останется нерелевантным для траектории студента.

**Литература:**

- _Deep Learning on a Data Diet_ (Sorscher et al., NeurIPS 2021) [[5]](https://arxiv.org/pdf/2107.07075) показывает, что для отбора данных информативна **норма градиента** (или эквивалентно — EL2N / per-token loss), а не его направление. Норма отражает "сложность" примера для модели.
- _When Less is More_ (Marion et al., 2023) [[6]](https://arxiv.org/pdf/2309.04564) подтверждает, что в претрейне LLM направление градиента слишком шумное, и стабильным сигналом является per-token loss (перплексия).

**Вывод:** Проблема ортогональности градиентов решаема через проекции (лемма JL), но это не делает предложенный подход рабочим. Даже корректно вычисленный центр масс градиентов учителя бесполезен для студента из-за нестационарности весов. Информативным сигналом для отбора данных является **норма градиента** (per-token loss), а не его направление.

### Проблема 4: Математическое противоречие с сохранением дисперсии

**Утверждение:** Можно отобрать малое число представителей кластера так, чтобы их суммарный градиент совпадал с центром масс, **и при этом сохранить дисперсию** кластера.

**Проблема:**
Если подмножество $S \subset C$ подобрано так, что:
$$\frac{1}{|S|} \sum_{j \in S} g_j \approx \frac{1}{|C|} \sum_{i \in C} g_i$$
то **дисперсия градиентов внутри $S$ не обязана совпадать с дисперсией внутри $C$**. Более того, при малом $|S|$ и жестком ограничении на сумму, дисперсия $S$ обычно **меньше** дисперсии $C$.

Сохранить малым числом точек одновременно и среднее, и дисперсию — задача принципиально более сложная, так как требует контроля двух разных статистических моментов. Совпадение центра масс гарантирует лишь правильное среднее, но игнорирует разброс. У малого подмножества физически не хватает степеней свободы, чтобы одновременно попасть в центр и воспроизвести многомерный разброс. Подгонка под среднее часто вынуждает выбирать точки ближе к центру, искусственно убивая дисперсию. Поэтому для сохранения формы распределения простого отбора недостаточно: нужны либо веса, либо явная оптимизация по второму моменту, либо кратное увеличение размера выборки.

**Оговорочка:** наверное, можно сохранить дисперсию, квотируя по сложности (PPL для прокси), но нужно отдельно обдумывать, так как непонятно, как это считать

**Литература:**

- В _Dataset Condensation with Distribution Matching_ (Zhao & Bilen, WACV 2023) [[3]](https://arxiv.org/pdf/2110.04181) показано, что для сохранения распределения данных необходимо матчить **распределения** через Maximum Mean Discrepancy (MMD), а не только средние значения. матчинг только первого момента (среднего) приводит к потере информации о дисперсии.
- Для реальных данных (Core-Set Selection) сохранение дисперсии внутри кластера достигается **стратифицированной выборкой** по сложности (например, по перцентилям per-token loss), как в _Deep Learning on a Data Diet_ [[5]](https://arxiv.org/pdf/2107.07075).

**Вывод:** Сохранить дисперсию кластера, просто подбирая примеры с совпадающей суммой градиентов, невозможно. Требуется явная стратификация по сложности (Easy / Core / Hard квоты).

### Проблема 5: Отсутствие доступа к тестовому датасету

**Утверждение:** Подход работает без валидационного/тестового датасета.

**Проблема:**
Без доступа к тесту предложенный подход **не поддаётся верификации**. Невозможно определить, улучшает ли селекция качество модели, так как нет независимой метрики.

Более того, ключевые методы, на которые опирается идея, **математически требуют** валидационного множества:

**Литература:**

- _GRAD-MATCH_ (Killamsetty et al., ICML 2021) [[8]](https://arxiv.org/pdf/2103.00198) формулирует задачу как:
  $$\min_{S} \left\| \nabla L_{\text{val}}(\theta) - \frac{|D|}{|S|} \sum_{j \in S} \nabla L_j(\theta) \right\|$$
  где $\nabla L_{\text{val}}$ — градиент на валидационном множестве. Без валидации целевой градиент не определён.
- _Rethinking Data Selection at Scale_ (Xia et al., 2024) [[10]](https://arxiv.org/pdf/2410.09335) показывает, что на SFT-датасетах масштаба 2М+ примеров **почти все self-scoring методы не превосходят случайный выбор** при отсутствии валидационного сигнала.

**Вывод:** Без доступа к тесту невозможно ни оценить качество селекции, ни применить GradMatch-подобные методы. Любое утверждение о "сохранении направлений" становится непроверяемым.

### Предложение

Для задачи претрейна 0.6B без доступа к тесту литература предлагает следующий подход:

1. **Прокси-скоринг вместо градиентов учителя.** Использовать per-token loss (PPL) от готовой same-language прокси-модели для оценки сложности примеров [[6]](https://arxiv.org/pdf/2309.04564)[[9]](https://arxiv.org/pdf/2406.11794).
2. **K-Means вместо DBSCAN.** Сферическая кластеризация с косинусным расстоянием для тематического разбиения [[4]](https://arxiv.org/pdf/2305.06677)[[9]](https://arxiv.org/pdf/2406.11794).
3. **Стратификация по сложности вместо матчинга градиентов.** Квотирование Easy / Core / Hard внутри каждого кластера для сохранения дисперсии [[5]](https://arxiv.org/pdf/2107.07075).
4. **Дедупликация и фильтрация шума.** MinHash + PPL-префильтр вместо градиентной атрибуции [[9]](https://arxiv.org/pdf/2406.11794)[[10]](https://arxiv.org/pdf/2410.09335).
5. **Оценка через held-out subset.** Если нет внешнего теста, необходимо выделить внутренний held-out набор из претрейн-корпуса для оценки PPL-динамики [[6]](https://arxiv.org/pdf/2309.04564).
