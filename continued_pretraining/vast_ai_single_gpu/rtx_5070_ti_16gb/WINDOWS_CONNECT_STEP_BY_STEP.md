# Vast.ai с Windows: инструкция «куда нажимать» для PuTTY и WinSCP

Эта инструкция рассчитана на человека, который раньше не подключался к
удалённому Linux-серверу. Проходите её сверху вниз и не арендуйте instance,
пока не закончите раздел с SSH-ключом.

## Сначала — что здесь вообще происходит

После аренды Vast выдаёт вам удалённый компьютер с Linux и GPU.

- **PuTTY** открывает чёрное окно-терминал этого удалённого компьютера. В нём
  вводятся команды Linux.
- **WinSCP** показывает файлы двумя панелями: слева ваш Windows-компьютер,
  справа удалённый Vast-компьютер.
- **PuTTYgen** один раз создаёт электронный ключ для входа. Это маленькая
  отдельная программа из комплекта PuTTY, а не режим внутри основного окна
  PuTTY.

Vast не выдаёт пароль для пользователя `root`. Вход устроен так:

```text
PuTTYgen
├── public key  ──копируем текст──> Vast.ai
└── private key ──сохраняем .ppk──> только ваш Windows
                                      ├── PuTTY
                                      └── WinSCP
```

Публичный ключ не является секретом. Приватный `.ppk` нельзя загружать на Vast,
отправлять другим людям или класть в репозиторий.

## Шаг 0. Проверить, есть ли PuTTYgen

1. Нажмите клавишу `Win` или кнопку «Пуск».
2. Начните печатать `PuTTYgen`.
3. Если появляется приложение **PuTTYgen**, откройте его и переходите к
   следующему разделу.

Если поиск находит только **PuTTY**, вероятно, у вас скачан один отдельный
`putty.exe`, а не установлен полный комплект.

### Если PuTTYgen отсутствует

1. Откройте официальную страницу:
   <https://www.chiark.greenend.org.uk/~sgtatham/putty/latest.html>
2. В разделе `MSI (Windows Installer)` выберите обычный **64-bit x86**
   installer. Для большинства компьютеров нужен именно он, не ARM и не 32-bit.
3. Запустите скачанный `.msi`.
4. В установщике нажимайте `Next`, оставьте стандартный путь и завершите
   установку.
5. Снова откройте «Пуск» и найдите `PuTTYgen`.

Можно скачать только отдельный `puttygen.exe` с той же официальной страницы,
но полный MSI-комплект проще и добавляет программы в меню «Пуск».

Не скачивайте PuTTYgen с сайтов-каталогов программ.

## Шаг 1. Создать ключ в PuTTYgen

Этот шаг выполняется один раз.

1. Откройте **PuTTYgen**.
2. Внизу окна найдите `Parameters`.
3. В `Type of key to generate` выберите `RSA`.
4. В `Number of bits in a generated key` укажите `4096`.
5. Нажмите кнопку `Generate`.
6. Двигайте мышью внутри пустой области окна, пока зелёная полоса не дойдёт до
   конца.
7. После генерации в поле `Key comment` можно написать `vast-ai`.

Ниже находятся поля:

- `Key passphrase`;
- `Confirm passphrase`.

Безопаснее придумать passphrase и ввести её дважды. Тогда PuTTY и WinSCP будут
спрашивать её при подключении. Если оставить поля пустыми, подключаться проще,
но любой человек, получивший `.ppk`, сможет использовать его без
дополнительного пароля.

### Сохранить приватный ключ

1. Нажмите `Save private key`.
2. Если passphrase пустая, PuTTYgen покажет предупреждение. Подтвердите только
   если осознанно хотите ключ без passphrase.
3. Создайте на Windows понятную папку, например:

```text
C:\Users\<ваше_имя>\Documents\SSH\
```

4. Сохраните файл под именем:

```text
vast-ai.ppk
```

Это приватный ключ. Он остаётся только на вашем компьютере.

### Скопировать правильный публичный ключ

В верхней части PuTTYgen есть большое текстовое поле с подписью:

```text
Public key for pasting into OpenSSH authorized_keys file
```

1. Кликните внутри этого поля.
2. Нажмите `Ctrl+A`.
3. Нажмите `Ctrl+C`.

Текст начинается примерно с `ssh-rsa` и заканчивается комментарием `vast-ai`.
Скопировать надо **всю строку целиком**.

Кнопка `Save public key` для Vast не обязательна. Главное — скопировать текст
именно из большого верхнего поля.

Пока не закрывайте PuTTYgen: если потеряете скопированный текст, его можно
скопировать ещё раз.

## Шаг 2. Добавить публичный ключ в Vast.ai

Делайте это **до аренды instance**.

1. В браузере войдите в свой аккаунт Vast.ai.
2. Откройте страницу:
   <https://cloud.vast.ai/manage-keys/>
3. Найдите секцию SSH Keys.
4. Нажмите кнопку добавления ключа: в зависимости от версии интерфейса она
   может называться `Add SSH Key`, `Add Key` или иметь значок `+`.
5. В поле ключа вставьте `Ctrl+V` текст из верхнего поля PuTTYgen.
6. Если есть отдельное поле имени/label, напишите `home-windows-putty`.
7. Нажмите `Save`/`Add`.

После сохранения в списке должен появиться ключ, начинающийся с `ssh-rsa`.

Не вставляйте туда содержимое `.ppk` и не загружайте сам `.ppk`. Vast нужен
только публичный текст.

Account-level key автоматически добавляется в **новые** instances. Если
instance был создан раньше ключа, самый понятный вариант для первого раза —
уничтожить ещё пустой instance и создать новый после добавления ключа.

## Шаг 3. Арендовать GPU

1. В Vast откройте страницу поиска GPU (`Search`).
2. Выберите количество GPU: `1`.
3. Так как локальный baseline выполнялся на RTX 3090 Ti 24 GB, сначала ищите:

   - RTX 3090 / 3090 Ti 24 GB — основной бюджетный вариант;
   - RTX 4090 24 GB — если выигрыш в скорости оправдывает цену;
   - 4070 Ti SUPER / 5070 Ti 16 GB берите только для дешёвого cloud-smoke:
     по VRAM они слабее вашей локальной карты;
   - обычная RTX 4070 Ti имеет лишь 12 GB и для этого проекта не рекомендуется.

4. Поставьте reliability не ниже `95%`.
5. Для первого раза включите Verified/Secure предложения.
6. Убедитесь, что у предложения есть direct ports.
7. Желательно:

   - system RAM 24–32 GB или больше;
   - хотя бы 4 CPU cores;
   - нормальные download/upload speed;
   - max duration длиннее вашего эксперимента.

8. Выберите **On-demand**, не Interruptible/Bid. Interruptible оставьте на
   второй запуск после проверки checkpoint/resume.
9. Нажмите `Rent`.

### Template и диск

После выбора предложения Vast попросит выбрать template/настройки:

1. Выберите **Recommended PyTorch** template.
2. Выберите SSH launch mode. Не выбирайте голый `ubuntu:latest`.
3. Установите container disk **50 GB** до создания instance.
4. Проверьте итоговую почасовую цену, storage и bandwidth.
5. Подтвердите создание.

Диск после создания увеличить нельзя.

## Шаг 4. Дождаться Running и получить три значения

1. Откройте в Vast страницу `Instances`.
2. Найдите созданную карточку.
3. Дождитесь состояния `Running`.
4. На карточке нажмите кнопку `SSH` или `Connect`.

Vast покажет одну или несколько команд. Direct-вариант выглядит примерно так:

```text
ssh -p 46230 root@142.114.29.158
```

Ваши цифры будут другими. Из этой строки выпишите:

| Что нужно | В примере | Откуда взять |
|---|---:|---|
| Host/IP | `142.114.29.158` | всё после `@` |
| Port | `46230` | число после `-p` |
| Username | `root` | текст перед `@` |

Не используйте IP и port из этого документа — это только пример.

Если Vast показывает `Direct SSH` и `Proxy SSH`, для PuTTY/WinSCP сначала
выбирайте Direct. Если Direct не соединяется, можно создать вторую PuTTY
session с host/port из Proxy-команды.

## Шаг 5. Настроить PuTTY — буквально по полям

Откройте основное приложение **PuTTY**, не PuTTYgen.

### 5.1. Главный экран Session

Слева должен быть выбран пункт `Session`.

Справа:

1. В `Host Name (or IP address)` введите только IP/host после `@`.
2. В `Port` введите число после `-p`.
3. В `Connection type` выберите `SSH`.

Пример:

```text
Host Name: 142.114.29.158
Port:      46230
Type:      SSH
```

Не вставляйте в Host Name всю строку `ssh -p ...`, не пишите там
`root@142...` и не оставляйте стандартный port 22.

### 5.2. Указать пользователя root

В дереве слева:

```text
Connection
└── Data
```

Нажмите `Data`. Справа найдите:

```text
Auto-login username
```

Введите:

```text
root
```

### 5.3. Выбрать приватный `.ppk`

В дереве слева раскройте:

```text
Connection
└── SSH
    └── Auth
        └── Credentials
```

Если рядом с `SSH` или `Auth` стоит маленький `+`, сначала нажмите его.

Справа найдите:

```text
Private key file for authentication
```

1. Нажмите `Browse`.
2. Выберите сохранённый файл `vast-ai.ppk`.
3. Нажмите `Open` в окне выбора файла.

### 5.4. Сохранить настройки, чтобы не вводить всё снова

1. В дереве слева снова нажмите самый верхний `Session`.
2. В поле `Saved Sessions` введите понятное имя, например:

```text
Vast-Qwen-5070Ti
```

3. Нажмите `Save`.

В следующий раз достаточно открыть PuTTY, выбрать это имя в списке, нажать
`Load`, затем `Open`.

### 5.5. Первое подключение

Нажмите `Open` внизу окна PuTTY.

При первом входе появится `PuTTY Security Alert` про неизвестный host key. Это
нормально для нового сервера. Убедитесь, что host/IP и port взяты из карточки
вашего instance, затем нажмите `Accept`.

Если вы задали passphrase в PuTTYgen, введите её. При вводе в Linux/SSH символы
могут не отображаться — это нормально.

Успешное подключение выглядит примерно так:

```text
root@C.123456:~#
```

Теперь команды, которые вы печатаете, выполняются не на Windows, а внутри
арендованного Linux-container.

Для проверки введите:

```bash
nvidia-smi
```

Должна появиться таблица с названием арендованной GPU. Ничего устанавливать и
запускать до этого момента не надо.

## Шаг 6. Настроить WinSCP

PuTTY пока можно оставить открытым.

1. Откройте WinSCP.
2. Нажмите `New Site`.
3. Заполните:

```text
File protocol: SFTP
Host name:     тот же Host/IP из Vast
Port number:  тот же нестандартный Port из Vast
User name:    root
Password:     оставить пустым
```

4. Нажмите `Advanced`.
5. Слева откройте:

```text
SSH
└── Authentication
```

6. В `Private key file` нажмите `...`/`Browse`.
7. Выберите тот же `vast-ai.ppk`.
8. Нажмите `OK`.
9. Нажмите `Save`, назовите site, например `Vast Qwen`.
10. Нажмите `Login`.

При первом входе WinSCP спросит о server fingerprint. Проверьте, что
подключаетесь к host/port своей карточки Vast, и нажмите `Accept`.

После подключения:

- левая панель — файлы вашего Windows;
- правая панель — файлы удалённого Vast.

## Шаг 8. Распаковать и проверить файлы в PuTTY

Вернитесь в чёрное окно PuTTY и по очереди выполните:

```bash
mkdir -p /workspace/qwen_vast
cd /workspace/qwen_vast
python3 -m zipfile -e /workspace/vast_ai_single_gpu_upload.zip .
ls -la
```

После `ls -la` среди файлов должны быть:

```text
README.md
requirements.txt
setup.sh
run_experiment.sh
benchmark.py
train.py
configs
src
```

Теперь:

```bash
chmod +x setup.sh run_experiment.sh status.sh pack_results.sh
```

## Шаг 9. Выбрать config

Используйте только один config:

| Арендованная GPU | Команда/config |
|---|---|
| 12 GB, например обычная 4070 Ti | `configs/vast_12gb.yaml` |
| 16 GB, например 4070 Ti SUPER/5070 Ti | `configs/vast_16gb.yaml` |
| 24 GB, например 3090/3090 Ti/4090 | `configs/vast_24gb.yaml` |

Ниже используется рекомендуемый пример для 24 GB. Если вы осознанно арендовали
16 GB, замените `vast_24gb.yaml` на `vast_16gb.yaml` **во всех командах**.

## Шаг 10. Подготовить окружение

В PuTTY:

```bash
cd /workspace/qwen_vast
./setup.sh configs/vast_24gb.yaml
```

Скрипт установит Python-зависимости и проверит CUDA, BF16, bitsandbytes, диск,
модель и датасет. Это может занять несколько минут.

Успех заканчивается строками:

```text
[preflight] PASSED
[setup] complete
```

Если видите `[FAIL]`, не начинайте training. Скопируйте весь текст ошибки.

## Шаг 11. Запустить эксперимент так, чтобы он не умер при закрытии PuTTY

Не запускайте долгий процесс просто командой `python train.py`. Используйте
`tmux`.

Для рекомендуемой 24-GB карты:

```bash
tmux new-session -d -s qwen-train \
  "cd /workspace/qwen_vast && ./run_experiment.sh configs/vast_24gb.yaml"
```

Команда ничего долго не печатает, потому что создала фоновую session. Чтобы
увидеть процесс:

```bash
tmux attach -t qwen-train
```

Теперь вывод эксперимента виден в окне.

### Как выйти из tmux, не останавливая training

1. Нажмите `Ctrl+B`.
2. Отпустите обе клавиши.
3. Нажмите `D`.

Не нажимайте `Ctrl+C`: это запрос на остановку процесса.

После detach можно закрыть PuTTY. Training продолжит работать на Vast.

### Как вернуться позже

1. Снова подключитесь через сохранённую session PuTTY.
2. Выполните:

```bash
tmux attach -t qwen-train
```

Если session уже закончилась:

```bash
tmux ls
cd /workspace/qwen_vast
./status.sh
```

## Шаг 12. Смотреть статус

Удобно открыть второе окно PuTTY с теми же настройками и выполнить:

```bash
cd /workspace/qwen_vast
./status.sh
```

Или смотреть GPU:

```bash
watch -n 2 nvidia-smi
```

Выйти из `watch`: `Ctrl+C`. Это остановит только `watch`, а training в другой
tmux session продолжится.

## Шаг 13. Скачать результаты

После завершения в PuTTY:

```bash
cd /workspace/qwen_vast
./pack_results.sh full
```

Команда напечатает имя файла примерно такого вида:

```text
exports/qwen_vast_full_20260729T120000Z.tar.gz
```

В WinSCP:

1. В правой панели откройте `/workspace/qwen_vast/exports`.
2. Перетащите `.tar.gz` на левую панель в выбранную локальную папку.
3. Дополнительно скачайте последний checkpoint из:

```text
/workspace/qwen_vast/outputs/<run_name>/checkpoint-XXXXXX/
```

Для продолжения обучения нужен checkpoint целиком, включая `optimizer.pt`.

## Шаг 14. Остановить оплату

1. Убедитесь, что архив и checkpoint появились на Windows.
2. Проверьте, что размеры файлов не нулевые.
3. Откройте Vast → `Instances`.
4. Нажмите `Destroy`/значок корзины у instance.
5. Подтвердите удаление.

`Stop` останавливает GPU compute, но storage продолжает тарифицироваться.
`Destroy` удаляет container и прекращает его storage billing, но после него
файлы восстановить нельзя.

## Частые ошибки

### `No supported authentication methods available`

Обычно означает одно из следующего:

- public key не добавлен в Vast;
- instance создан до добавления account key;
- в PuTTY выбран не тот `.ppk`;
- подключение идёт к другому host/port.

Проверьте ключ на странице Vast Keys и настройки
`Connection → SSH → Auth → Credentials`.

### `Network error: Connection timed out`

- instance ещё не имеет статуса `Running`;
- указан неправильный port;
- Direct endpoint временно недоступен;
- локальная сеть блокирует соединение.

Снова откройте `SSH/Connect` на карточке Vast и перепишите host/port. Если есть
Proxy SSH, попробуйте его данные в отдельной сохранённой PuTTY session.

### `Connection refused`

Обычно неверный port либо SSH внутри instance ещё запускается. Подождите
30–60 секунд, обновите карточку и снова скопируйте connection details.

### PuTTY спрашивает `login as:`

Введите:

```text
root
```

После подключения вернитесь в настройки и сохраните `root` в
`Connection → Data → Auto-login username`.

### PuTTY просит password пользователя root

Обычного root-пароля Vast не предоставляет. Не подбирайте пароль. Значит,
key-based authentication не сработала: проверьте public key и `.ppk`.

### В Host Name вставлена вся команда

Неправильно:

```text
ssh -p 46230 root@142.114.29.158
```

Правильно:

```text
Host Name: 142.114.29.158
Port: 46230
Username: root
```

### Закрыл PuTTY — training исчез

Если training запускался внутри `tmux`, он не исчез. Подключитесь снова:

```bash
tmux attach -t qwen-train
```

Если запускали без tmux, SSH-disconnect мог завершить процесс. Запустите
`run_experiment.sh` через команду из шага 11: pipeline найдёт последний полный
checkpoint и продолжит.
